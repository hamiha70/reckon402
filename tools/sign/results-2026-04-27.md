# KMS-account verify run — 2026-04-27

Spec: `specs/02-kms-signer.md`. Verifier: `tools/sign/verify-kms-account.mjs`.

## Invocation

```
unset AWS_PROFILE && \
  infisical run \
    --projectId 84d8a29b-27e3-46d0-bf72-bbe01215ac35 \
    --env dev \
    --domain https://secrets.intentralabs.com \
    -- node tools/sign/verify-kms-account.mjs
```

`AWS_PROFILE` is unset deliberately so the IAM-user access keys
hydrated from Infisical (one pair per KMS target) win in the AWS SDK
credential chain. The script swaps which pair is "active" between
the two targets.

## What this proves

| Property | How proven |
|----------|------------|
| KMS public-key DER parser correctly extracts the secp256k1 point | `account.address` matches both expected EOAs (independently derived offline by `tools/provisioning/derive-eoa-from-pem.mjs`) |
| KMS Sign DER signature parser handles real KMS output | Both `r` and `s` decode to non-zero 256-bit values in every case (otherwise recovery fails) |
| Low-S normalization is correct | `recoverMessageAddress` accepts the signature without an "s value out of range" error |
| `v` recovery loop terminates on yParity 0 or 1 | All 8 cases recovered on first or second try; "v-recovery exhausted" never thrown |
| viem `signMessage` -> `verifyMessage` round-trip works | EIP-191 personal-sign prefix path verified |
| viem `signTypedData` -> `verifyTypedData` round-trip works | EIP-712 typed-data path verified with a minimal `Probe(name string, nonce uint256)` schema |
| viem `signTransaction` -> `parseTransaction` + secp256k1 `recoverPublicKey` round-trip works | EIP-1559 raw-tx hex deserializes, sighash is reconstructed by re-serializing without sig fields, and the recovered sender matches the KMS-derived EOA |
| Address cache works without producing stale results | The same `kmsAccount({ keyAlias })` factory was invoked per target inside `withAwsCreds` and consistently returned the right address with the right credentials |

## What this does NOT prove

- **Broadcast.** No transaction was sent to any node. Broadcast is
  gated on Sepolia ETH funding for the deployer EOA (task C in the
  L0 work plan), which lands in a follow-up commit.
- **Lambda packaging.** The signing wrapper Lambda (L4 surface)
  reuses this adapter but adds its own deployment artefact. That's
  spec 11 work.
- **Concurrent-signer behaviour under heavy load.** `KMSClient` is
  thread-safe (Node has no threads, but its async pool is). For
  reckon402's < 1 sig/sec workload, contention is not a concern.
